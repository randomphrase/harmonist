{# The album's tracks against its MusicBrainz release, field by field (#135). The table's columns are `tracklist.columns` and each row's cells are `ComparedTrack.fields` in the same order — so both come from the model, rather than the headings being written out here and hoped to line up. Which columns those are is EARNED, per album (#309). A per-track tag gets one when it differs from MusicBrainz on some track, when the tracks disagree with each other, or when it differs from the album-level value; otherwise it is a column of N identical rows restating something the page already says, and it is named under the table instead with its one value a disclosure away. That is what puts a per-track change — an artist sort on track 6, an ISRC — beside the track it belongs to, where the re-tag box below could only ever state it as "1 of 7 tracks" and leave the reader to work out which. Two lines per track, not two columns: a track that agrees is one plain line, and a track that differs gains a second beneath it in mb-purple carrying only the cells that actually differ. Both values keep the same left edge and the same column, so a difference is a vertical scan rather than a comparison. Same register as the album panel above — most of these are formatting differences, not errors, and nothing is coloured as a mistake. A video track is a third shape (#226): present, marked, and carrying only its own values — Harmonist reads `.m4v` tags but never writes them, so comparing one against MusicBrainz would raise differences no re-tag could ever settle. Also serves the DISK-ONLY view, where MusicBrainz has deleted the release (#228). Every row is then PRESENT with no MusicBrainz counterpart, so `shows_mb` is false throughout and the table renders one plain line per track — no second layout, just the existing one with nothing to stack. #} {# The hexagon note, matching the album section's.
