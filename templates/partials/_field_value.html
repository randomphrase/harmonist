{# One value of the album's tag comparison, rendered the way its field wants. The seam between an ordinary tag — whose differing parts are marked in place by `_diff_runs` — and a row whose value is one or more MusicBrainz IDs (#298). A UUID has no parts worth marking: character-level emphasis across two hex strings is confetti, and the string itself carries nothing a reader can act on. So an id row becomes a link, captioned with the NAME the id stands for. **The name comes from the release we just fetched, and only from there.** An id the files carry that MusicBrainz has moved away from is not in `mb_names` and falls back to the raw hex — which is what keeps a differing row from rendering two identical names and reading as a match. The tooltip carries the id either way, so the value on disk is never more than a hover away. `value.split('; ')` undoes the join `compare._as_display` made. A round trip through a string, and safe only because no MBID can contain the separator — which is why this is here rather than being a general habit. The scheme and host are literal, so `id` cannot make this a `javascript:` URL; Jinja autoescapes it into the attribute, which is what keeps an off-box, unsanitised payload from being markup. An ARTIST CREDIT is the third shape (#309). "Rafael Anton Irisarri feat. Julia Kent" is not one value but two artists and the words MusicBrainz puts between them, and it reads far better as the two links it describes. The parts come from `mb_credits`, keyed by the phrase they build — so a credit is only ever applied to a value it spells character for character, and a tag that has drifted from MusicBrainz misses the lookup and renders as the flat string it is. Same fallback, and the same reason, as an id with no name. `credit` gates it rather than "does this value happen to be a credit phrase", because an album named after its artist would otherwise turn its Album row into an artist link. Expects `value`, `runs`, `entity` and `credit` from an enclosing {% with %}; `mb_names` and `mb_credits` come from the page context, since they are the same for every row. #} {%- if credit and value and mb_credits.get(value) -%} {%- for part in mb_credits[value] -%} {%- if part.mbid -%} {#- `mbid`, but never `mbid--raw`: a credit part is always a NAME, so it wants the surrounding prose face rather than the mono one an unresolved hex id falls back to. -#} {{ part.name }} {%- else -%} {#- MusicBrainz names this artist without identifying them. Plain text, not a dead link: there is nowhere for it to go. -#} {{- part.name -}} {%- endif -%} {{- part.join -}} {%- endfor -%} {%- elif entity and value -%} {%- for id in value.split('; ') -%} {%- if not loop.first %}; {% endif -%} {%- set name = mb_names.get(id) -%} {#- An id with no name is TRIMMED to its first characters (#319). A full UUID is 36 of them and none are readable; eight is ample to see that two ids differ, which is the only thing a reader does with one here. The whole id stays in the href and the tooltip, so nothing is lost — and the ellipsis says it was shortened rather than truncating in silence. Never applied to a NAME: that is the readable form, and cutting "Rafael Anton Irisarri" short would be the opposite of the point. -#} {{ name or (id[:8] ~ '…' if id|length > 8 else id) }} {%- endfor -%} {%- else -%} {%- with runs = runs, value = value %}{% include 'partials/_diff_runs.html' %}{% endwith -%} {%- endif -%}
